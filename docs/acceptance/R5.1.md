### 4.1 新增单写实例保护（代码级，本轮修复）

当前版本仅支持单实例。为避免“同一数据库被两个进程同时写入”，`internal/storage` 新增
`<db>.lock` 上的 `flock(LOCK_EX|LOCK_NB)`（`lock_unix.go`）：第二个 `Store.Open`/第二个
`onboardd` 立即失败并提示 `single-writer`；进程崩溃（包括 SIGKILL）由内核自动释放锁。
该锁在 R5.1+ 二进制中**无条件启用**（无配置开关/环境变量可关闭；`:memory:` 测试库除外）。
容器内同一 `/app/data` 卷被两个容器同时挂载时，该锁会阻止第二个写入实例（需 daemon 可用后实测）。

运维语义（重要）：

- **滚动升级**：旧版本（R5 及更早）二进制不获取该锁，因此“旧容器仍在写 + 新容器启动”存在**双写窗口**；
  升级必须先停旧实例再启动新实例（或先停服务再切镜像）。
- **迁移/备份工具**：服务运行时对同一 DB 执行 `onboardd migrate` 会被锁拒绝（这是期望的 fail-closed）；
  `scripts/restore.sh`/`rotate` 同样要求先停服务（与 R4 P1-5 的停机编排一致）。
- 锁是 advisory 文件锁：能删除 data 目录中 `<db>.lock` 的主体本就能写 DB/破坏数据，属同一信任边界；
  不把它当作对抗恶意本地用户的机制。
