## 2. R5-A 安全加固：服务端会话撤销持久化 — **PASS**

### 2.1 实现

| 层 | 变更 |
|---|---|
| 迁移 | `internal/storage/migrations/0003_session_revocations.sql`：`session_revocations(session_id PK, revoked_at_ms, expires_at_ms)` + 过期索引；版本行写入 `schema_migrations(3)` |
| 存储 | `internal/storage/sessions.go`：`RevokeSession`（upsert，幂等，扩展过期时间）、`SessionRevoked`（读池，过期即不生效）、`PruneSessionRevocations`（删除已过期行）、`CountSessionRevocations`（诊断） |
| API | `internal/api/server.go`：cookie 认证改为查询 SQLite 撤销表；读失败 **fail closed**（拒绝会话）。`internal/api/ui.go`：登出先持久化撤销、成功后才清 Cookie；持久化失败返回 500，不清 Cookie（避免"看似登出、实际仍可重放"） |
| 清理 | 登录时机会式 `PruneSessionRevocations`，表规模有界，无需额外维护进程 |

数据库兼容：迁移是**增量**的；已有 v2 数据库在下次 `Open` 时自动应用 0003 并升到 schema 3，原有表/数据不动（见 2.3 的 v2 升级回归）。
