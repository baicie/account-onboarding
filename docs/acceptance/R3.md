## 3. 契约实现清单（对照 task-3 要求）

### 3.1 `internal/provider/github`（既有账号邮箱管理，官方 REST only）

- 实现 `provider.EmailManager`（`Descriptor`/`AddEmail`/`ListEmails`）与可选
  `provider.CredentialVerifier`（`Verify`），编译期断言：
  `var _ provider.EmailManager = (*Adapter)(nil)`、`var _ provider.CredentialVerifier = (*Adapter)(nil)`。
  `Descriptor().Kind = provider.KindEmail`，可直接 `reg.AddEmailManager(adapter)`；
  `Verify` 保留为同适配器的可选能力（不建议同时注册到 credential 槽，避免 catalog 条目重名）。
- 令牌：`Config.TokenRef` 必须是 `secret://` opaque reference（原始 token 会被
  `New` 以 `VALIDATION` 拒绝）；每次调用通过 `provider.SecretResolver.Resolve` 取明文；
  Adapter 结构体不保存明文（测试用反射遍历字段验证），错误摘要 / DTO / 请求 URL 均不含令牌。
- `AddEmail`：`POST {base}/user/emails`，请求体 `{"emails":["..."]}`；`201/200` 读取返回数组，
  若未回显该地址则用 `GET /user/emails` 对账；`409` 或 `422` 且 body 含
  `already/duplicate/exists` 视为幂等成功并经 `GET /user/emails` 确认；对账不到该地址则
  `VALIDATION`（提示人工 reconcile），其他 `422` 直接 `VALIDATION`。
- `ListEmails`：`GET {base}/user/emails?per_page=100`，解析 `email`/`verified`/`primary`/`visibility`。
- Base URL allowlist：默认且生产唯一允许 `https://api.github.com`；仅当
  `Config.AllowLoopbackHTTP=true` 时允许 `http(s)://127.0.0.1[:port]`、`http(s)://[::1][:port]`、
  `http(s)://localhost[:port]`；拒绝其它主机、path/query/userinfo/非 http(s) scheme。
- 自定义 `http.Client{Timeout}`；`CheckRedirect` 拒绝跨 host/scheme 跳转（Authorization 不会
  离开 allowlist）；单响应体上限 1 MiB。
- 状态映射：`401/403 → NOT_AUTHORIZED`（403 且 `X-RateLimit-Remaining: 0`/`Retry-After`
  时按真实限流映射 `RATE_LIMITED`，见 §5 说明）、`404 → VALIDATION`、`409/422` 幂等处理、
  `429 → RATE_LIMITED`（Retry-After 秒数或 HTTP-date）、`5xx → UPSTREAM_TRANSIENT`、
  超时 → `TIMEOUT_UNCERTAIN`、非 JSON/schema 不符 → `PROVIDER_BUG`、跨 host 跳转 → `PROVIDER_BUG`。
- 无账号创建路径：源码扫描测试（禁止 signup/captcha/浏览器自动化/`/users` 等概念）+
  请求路径 allowlist 断言（仅 `/user/emails`、`/user`）+ 每个 httptest handler 拒绝 allowlist 外路径。

### 3.2 `internal/provider/workbuddy`（权限门禁的控制面 OAuth）

- 实现 `provider.OAuthProvider`：`var _ provider.OAuthProvider = (*Adapter)(nil)`。
- `Start`：`POST {base}/panel/api/login/start`，body `{"realm":"global"}`（默认；允许
  `global`/`cn`），`Authorization: Bearer <resolved gateway key>`（未配置时省略）；
  解析 `{"ok":true,"url":...,"state":...,"realm":...}`；state 写入 `provider.SecretStore`
  （kind `workbuddy_authorization_session`），返回 `AuthorizationSession{Ref:"secret://oauth/workbuddy/<random>", AuthorizationURL, ExpiresAt}`；
  `ExpiresAt = now + SessionTTL`，默认/上限均 15 分钟（对齐网关 `loginTTL`）。
- `Poll`：读取 secret store 中的 state → `GET {base}/panel/api/login/poll?state=<state>`；
  `200 {done:false}` → `PENDING`；`200 {done:true}` → `AUTHORIZED` + `CredentialRef`
  （`secret://workbuddy/credential/<uid>`，仅记录 pointer JSON：uid/realm/gateway base；
  **不读取、不落库、不返回任何 token**）；`410 → AUTH_EXPIRED`（engine 映射
  `REAUTHORIZE_REQUIRED`）；`401/403 → NOT_AUTHORIZED`；`429 → RATE_LIMITED + Retry-After`；
  `5xx/网络 → UPSTREAM_TRANSIENT`；超时 → `TIMEOUT_UNCERTAIN`；schema 不符 → `PROVIDER_BUG`。
- 单次使用 / 禁止重放：`410`、本地 15 分钟到期、授权成功后都删除 secret store 中的 state；
  每个 session ref 有 single-flight 锁 + 终态缓存（1h / 4096 条上限），重复 poll 直接返回终态，
  **不会再向网关发送同一个 state**（并发双 poll 测试断言网关只被调用 1 次）。
- 配置门禁：`Config.Enabled` 默认 `false`；`RestrictionReason` 默认
  `"WorkBuddy live adapter requires verified platform written permission; disabled by default"`；
  禁用时 `Descriptor().Enabled=false`、`Start/Poll` 在**任何网络调用和 secret 读取之前**
  返回 `NOT_AUTHORIZED`。
- Base URL allowlist：只允许 loopback（127.0.0.1/::1/localhost）与 RFC1918/ULA 私网地址；
  拒绝所有公网 IP 与 DNS 名（不解析 DNS，防 rebinding）；默认要求 `https`，仅当
  `Config.AllowTestHTTP=true` 时允许 loopback `http`（httptest 用）。
- 合规：源码扫描测试禁止已知上游主机、`/v2/plugin`、`/panel/api/login/cancel`、浏览器自动化、
  cookie/localStorage、`access_token`/`refresh_token` 等 token 提取标识。

## 6. 需要操作者提供什么才能跑 live

### 6.1 GitHub live（显式 opt-in，仅本机、仅操作者本人账号）

1. 一个操作者**本人合法持有**的现有 GitHub 账号（不得创建新账号）。

## 8. 已知限制 / 说明

- `internal/provider/boot/live.go` 的 `buildLive` 仍为空实现（R0 stub），R3 适配器尚未接线；

- GitHub `403` 在 `X-RateLimit-Remaining: 0` 或带 `Retry-After` 时按 GitHub 官方语义映射
  `RATE_LIMITED`（可重试）；普通 `403` 仍为 `NOT_AUTHORIZED`。这是对“401/403 → NOT_AUTHORIZED”
  的补充而非替代，两类都有测试覆盖。
- WorkBuddy `Poll` 的终态缓存只保存“结果”而不保存任何 token；缓存条目 1 小时过期、上限 4096，
  过期后重复 poll 会得到 `AUTH_EXPIRED`（不会重放旧 state）。
