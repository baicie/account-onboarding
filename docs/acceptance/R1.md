## 5. Cloudflare 错误映射（实现并测试的完整表）

| 上游情况 | errs.Class | 说明 |
|---|---|---|
| 400 / 422 | `VALIDATION` | 请求被拒（域名非法、name 非法等） |
| 401 / 403 | `NOT_AUTHORIZED` | admin 密码/站点密码/JWT 被拒 |
| 404（create / parsed_mails） | `PROVIDER_BUG` | 固定端点缺失 = 部署与契约不一致，必须可观测 |
| 404（GetMessage detail） | 触发回退；回退仍无 → `NOT_FOUND` | 兼容"detail 端点不存在"与"消息不存在"两种部署 |
| 405（detail） | 触发列表扫描回退 | 同上 |
| 409 / 400+重复标记 | 有界一次 `enablePrefix=true` 恢复；仍重复 → `CONFLICT` | 不无限重试 |
| 410 | `AUTH_EXPIRED` | 地址 JWT 失效（engine → REAUTHORIZE_REQUIRED 语义由上层决定） |
| 429 | `RATE_LIMITED` + `RetryAfter` | 解析 `Retry-After`（秒数或 HTTP-date） |
| 5xx | `UPSTREAM_TRANSIENT` | 携带 `HTTPStatus` |
| 传输超时 —— create | `TIMEOUT_UNCERTAIN` | 写操作可能已落地，需上层 reconcile |
| 传输超时 —— list/get | `UPSTREAM_TRANSIENT` | 读操作可安全重试 |
| 连接失败/DNS 等 | `UPSTREAM_TRANSIENT` | 带 cause 供本地诊断，cause 不含凭据 |
| 跨源 3xx | `PROVIDER_BUG` | 凭据绝不转发；目标未收到请求 |
| 非 JSON / schema 漂移 | `PROVIDER_BUG` | 错误文本仅含 HTTP 状态码，不含响应体 |
| 凭据无法解析 | `NOT_AUTHORIZED` | 不包装底层错误（避免凭据进入错误链） |
| 未分类错误 | `PROVIDER_BUG`（`errs.ClassOf` 默认） | 不盲目重试 |

## 6. 安全证据

1. **不落日志**：源码不引用 `log`/`log/slog`（§3 命令 10 无匹配）；适配器不打印请求/响应/凭据。
2. **错误安全**：所有 HTTP 错误只包含 `op` + HTTP 状态码；响应体、请求头、URL 查询（仅
   `limit/offset`）不进入 summary；`TestSecretsNeverAppearInErrors` 及每个映射测试断言
   admin 密码、站点密码、JWT、`"Bearer "` 不出现在 `Error()`、`errs.SummaryOf`、`%#v` 中。
3. **Secret 边界**：JWT 只在 `CreateAddress` 内短暂存在，立即经 `provider.SecretWriter`
   写入 `secret://mailbox/<id>`；只有 opaque ref 进入 `provider.Mailbox`（`json:"-"`）。
   与 `internal/secrets.Service.Put` 的 "kind 必须等于 ref kind" 契约一致（kind=`mailbox`），
   并用仿 `secrets.Service` 的测试锁死（`TestSecretStoreKindContract`）。
4. **SSRF/重定向**：构造期 pin host；默认仅 `api.moonbyte.top` + https；loopback 需显式
   `AllowLoopback: true`（测试专用，报告与代码注释均标注）；`CheckRedirect` 拒绝任何
   scheme/host/port 变化，测试证明跨源目标 0 请求。
5. **Mailpit 门禁**：BaseURL 仅允许 loopback（`127.0.0.0/8`、`::1`、`localhost`），拒绝
   userinfo/query/fragment；同源 redirect 之外一律拒绝。
6. **瞬态正文**：`provider.Message.Text/HTML` 依赖冻结契约的 `json:"-"`；
   `mailx.Result` 额外实现脱敏 `String()`/`MarshalJSON`。
7. **无凭据进入测试**：测试使用 `admin-password-must-never-leak` 等显式假值；无真实凭据。

## 8. Cloudflare 响应 normalizer（已实现并文档化）

- **列表 envelope**：按顺序尝试 `results` → `parsed_mails` → `mails` → `messages` → `data`
  → `items` → `list`；值为数组即采用，`null` 表示空列表；裸数组直接使用；其余 schema →
  `PROVIDER_BUG`（避免把接线错误伪装成"没有邮件"）。
- **mail item**：`id`（`id/mail_id/message_id/msg_id`）可为 number/string；`subject`；`from`
  （string / `{Address,Email,Name,Value}` / 数组取第一个）；`to`（string / 对象 / 数组；
  string 按 RFC5322 逗号拆分）；`received_at/created_at/created/date/time/timestamp`；
  `text/body/content`；`html`。支持 `{"raw": "RFC822..."}` 与 `{"raw": {..., "headers": {...}}}`；
  直连字段优先于 raw；无法识别的 item 被跳过（单个占位行不会毁掉整页）。
- **RFC822 解析**：header 折行展开、大小写不敏感、`Subject/From/To/Date/Message-ID`；
  正文放在 `Text`，形似 HTML 的正文同时放入 `HTML`。
- **时间**：`RFC3339Nano`、`RFC3339`、`2006-01-02T15:04:05`、`2006-01-02 15:04:05 [-0700]`、
  `RFC1123(Z)`、`RFC822(Z)`、`ANSIC`、`UnixDate`、`RFC850`、epoch 秒/毫秒/微秒；失败 →
  零值（由 mailx 时间窗安全拒绝，不猜测）。
- **ID 回退**：无 id 时对 `subject|sender|recipient|received|text|html` 做 SHA-256 派生
  `cf-auto-<16 hex>`，跨轮询稳定，保证去重语义。
- **GetMessage**：先 `GET /api/parsed_mail/{id}`（真实上游路径待 live 验证）；404/405 回退到
  `parsed_mails` 扫描（配置 `DisableDetailEndpoint` 可强制回退）。detail 响应支持直接对象或
  `results/mail/data/result/item/parsed_mail` 包装。

## 11. 已知限制与风险

1. **Cloudflare live schema 未冻结**（最高风险）：`results`/`parsed_mails`/裸数组三种 envelope、
   `raw` string/object、detail 路径 `/api/parsed_mail/{id}` 均按任务/ docs/08 与上游项目行为实现并
   测试，但**未对 `api.moonbyte.top` 实测**。若实际部署不同，会以 `PROVIDER_BUG` 显式暴露
   （不会静默误判为"没有邮件"），届时按真实响应补 normalizer 即可。
2. **GetMessage detail 404 二义性**：404 既可能"消息不存在"也可能"端点不存在"，适配器一律先回退
   扫描列表；这会多一次请求，且不能区分两种原因（最终仍以扫描结果为准）。
3. **409 重复地址恢复不是地址级幂等**：admin API 没有按 idempotency key 查询既有地址的端点，
   适配器只能做**一次** `enablePrefix=true` 有界重试；真正的重复防护仍依赖 engine 的幂等
   key/单 run 语义。两次 409 → `CONFLICT`，不循环。
4. **分页有界**：默认 `ListLimit=20`、`MaxPages=3`、`MaxMessages=200`（可配置）；验证邮件场景足够，
   但异常大量邮件时可能看不到更早的页。
5. **Mailpit `DeleteAddress`**：Mailpit 无按收件人删除端点，适配器枚举（`MaxMessages` 上限）后逐条
   `DELETE /api/v1/message/{id}`；共享 sink 上只删本地址邮件，404 视为幂等成功。
6. **mailx 单收件人字段**：冻结契约 `provider.Message` 只有一个 `Recipient`；适配器取 `To` 的第一个
   地址，多收件人邮件可能被精确匹配拒绝（宁漏勿错）。`To` 为空但主题/发件人匹配的邮件也会被拒绝。
7. **mailx 默认提取为启发式**：关键词 24 字符窗口、独立 6–8 位数字、字母数字需含数字、URL 与
   `<script>/<style>` 内的数字不视为 OTP；已提供 `LinkPatterns`/`OTPPatterns` 覆盖。链接排序按
   关键词得分，极端模板可能需要自定义 pattern。
8. **mailx 去重为进程内状态**：重启后依赖 engine 的持久化 `ConsumeMessage`（`internal/workflow`
   已实现）或 `MarkSeen` 预加载；适配器本身不持久化任何消息 ID。
9. **时钟偏移默认 2 分钟**（`mailx.Config.ClockSkew` 零值时）；engine 接线时建议显式设置。
10. **Mailpit `CreateAddress` 忽略 `EnablePrefix`**：sink 没有前缀概念，地址由 `Name`/`Key` 派生；
    这与 Cloudflare 语义不同，已在代码注释与报告中标注。
11. **测试等级**：本报告所有通过项均为 MOCK（httptest 上游），不代表真实 Cloudflare/Mailpit/
    Keycloak 已联通；按 docs/11 不得把 MOCK 结果称为 LIVE 成功。
