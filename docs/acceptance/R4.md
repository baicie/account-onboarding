## 9. 偏差与限制

1. **R4 “Sandbox 可靠性回归”**：本轮用 fake provider 完整工作流（邮箱→验证邮件→OIDC→凭据校验）执行 5+30；
   R2 的真实 Keycloak+Mailpit sandbox 未在本轮执行，不能互相替代。
2. **RBAC 为最小双角色**：admin/viewer 两个共享令牌，无 per-user 账号、2FA、角色管理；viewer 是只读令牌，
   适用于看板/巡检，不具备按人审计能力（P2-11）。
3. **速率限制为进程内固定窗口**：单实例自托管有效；多副本/重启场景需在反代层限流（P2-10）。
4. **加密快照仍需 keyring 分离保存**：工具已内置 AES-256-GCM、checksum、key_version 与 fail-closed；keyring 仍必须独立介质保存，
   否则介质失窃 + keyring 同机时仍可解密（docs/12 要求）。
5. **Docker**：只做了 `docker compose config` 静态验证；镜像 build/run、容器健康检查、read-only/非 root 的运行时行为
   均为 NOT_RUN（无 daemon）。
6. **Go `go run` 退出码**：`go run` 将子进程非零码归一为 1；精确退出码证据使用编译二进制（§2 #18）。
7. **并发写测试**：`TestBackupSnapshotWhileWALActive` 在快照期间真实并发写 run，证明 VACUUM INTO 的 WAL 一致性；
   但未做 kill -9 崩溃注入（不在 R4 本轮范围）。
8. **本机临时证据**：`/tmp/r4-evidence/**` 不随仓库提交，复跑命令见 §2/§10；密钥/测试 token 均在本机生成，未打印。
9. **扫描器仍为启发式**：R4c 通过 path-like span 修复长路径误报，并扩展 action-token/session/api-key 形状；规则仍可能对
   非典型编码/多行 base64 产生漏报或误报，生产环境应结合已知 secret 列表（`--known-secrets-file`）与人工复核。
10. **preflight 是操作前置**：compose 不会自动执行 preflight；CI/runbook 需显式调用，否则仍依赖操作者纪律。
