## 4. Behavioural evidence (from the smoke transcript)

- Liveness `/healthz` → `{"status":"ok"}`; `/readyz` without auth → **401**;
  with bearer → `{"ready":true,"schema_version":2,"wal":"wal"}`.
- Sandbox run (`sandbox-email-verify-oidc`, fake providers) → **COMPLETED** with
  steps `validate → prepare_mailbox → request_verification → wait_email →
  oauth → verify_credential`, all `SUCCEEDED`; event timeline contains
  `RUN_CREATED`, `STEP_STARTED`, `STEP_SUCCEEDED`, `OAUTH_STARTED`,
  `RUN_COMPLETED`.
- Event payload keys are limited to the allowlist: `attempt, deadline_at,
  failure_class, next_retry_at, operation_key, provider, reason, resume_state`.
- Idempotency: same `Idempotency-Key` + same body → same run id; different body
  → **409 CONFLICT**; unknown JSON field `account_count` → **400 VALIDATION**.
- Operator actions: a real-account run reaches `WAITING_USER_ACTION`
  (`action_required=true`); `resume` → **202**; `cancel` → **202** → `CANCELLED`;
  second cancel on a terminal run → **409**.
- Console: login page **200**, login with loopback Origin **303**, dashboard
  **200**, run page **200**, mutation without CSRF **403**.
- Leak scan over run JSON, event JSON and console HTML: no `secret://` refs, no
  JWTs (`eyJ...`).
- Restart durability: SIGTERM, restart with the same DB and master key → the
  completed run is still present with 6 steps, idempotent replay still matches,
  and a new run completes (encrypted secrets round-trip with the persisted key).

## 6. Known gaps / risks at R0

1. Only fake providers are complete in R0; live adapters are wired in R1/R3 and
   gated by config. R2 sandbox E2E is still in progress.
2. The SQLite driver uses cgo; the image therefore needs a C toolchain at build
   time (documented in `Dockerfile`). A driver swap would be contained to
   `internal/storage/store.go`.
3. `go test ./...` may be transiently red while teammates add new packages in
   parallel; the R0 gate above pins the R0 package set, and the final gate is
   re-run repo-wide once R2/R4 land.
4. No rate limiting on the control plane yet (R4).
5. Cursor pagination is `(created_at_ms, id)`-based; runs are immutable in
   creation ordering, so no drift is observed in tests.
