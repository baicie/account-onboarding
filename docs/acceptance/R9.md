## 2. P0 — 外部写入闸门（最高优先级）

事件日志不再是互斥/授权原语；migration 0004 `external_operations` 为权威状态：

- 状态：`PREPARED`、`IN_FLIGHT`、`CONFIRMED`、`OUTCOME_UNKNOWN`、`RECONCILIATION_REQUIRED`、`FAILED_DEFINITE`、`RESOLVED`。
- `BeginExternalOperation` 原子写 PREPARED 意图；`MarkExternalOperationInFlight` 是唯一的 PREPARED→IN_FLIGHT CAS 许可，并再次校验 run lease owner/generation；并发候选只有一个 winner。
- 只有 `FAILED_DEFINITE` 可再次 Begin；`IN_FLIGHT`/`OUTCOME_UNKNOWN`/`RECONCILIATION_REQUIRED`/`CONFIRMED`/`RESOLVED` 一律阻止自动重试。
- 超时、响应丢失、上游错误、provider bug、gate 后的取消 → `OUTCOME_UNKNOWN`；重复地址/冲突 → `RECONCILIATION_REQUIRED`。
- 完成失败/commit 失败保持 IN_FLIGHT（保守，不重试）；成功先 CONFIRMED 再返回步骤结果。CONFIRMED 后 step commit 失败时，提供 audited RESOURCE_CONFIRMED/MANUAL_COMPENSATION_COMPLETED 恢复路径（仍不自动重试）；IN_FLIGHT 只有在 run lease 过期后才允许人工 close。
- `/readyz` 要求 schema 4 + `external_operations` 表；缺失即未就绪。

确定性测试（不依赖 sleep 竞态）：PREPARED 写入失败（drop table 后 Begin 失败）、PREPARED 后未知、未知后不可被 FAILED 覆盖、FAILED_DEFINITE 可重试、stale owner/generation 拒绝、8 并发 Mark 仅 1 winner、timeout 后 provider 调用次数 **1**、重启后状态保留、人工 resolve 后仍不可自动重试、审计行原子写入、错误 key 恢复 fail-closed。

## 3. P1 — 分页与计数

`GET /v1/ops/external?status=&provider=&run_id=&limit=&cursor=` 返回 `items`、`next_cursor`、`global status_counts`、`total_needs_reconciliation`、`query_scope`、`generated_at`。排序为 `(created_at_ms DESC, id DESC)`，cursor 绑定两者；先过滤后分页；计数来自索引表的全局 GROUP BY，不基于当前页；无界内存聚合被禁止。201/1000/10000 行分页无重复/遗漏，`EXPLAIN QUERY PLAN` 使用 `idx_external_ops_status_created`。

## 4. P2 — 人工对账

`POST /v1/ops/external/{id}/resolve`（admin-only；Cookie 走 CSRF/Origin，Bearer 需 admin）：

```json
{"resolution":"RESOURCE_CONFIRMED","reason":"verified mailbox exists","expected_version":3,"evidence_reference":"ticket-123"}
```

- resolution 枚举：`RESOURCE_CONFIRMED`、`NO_RESOURCE_CREATED`、`MANUAL_COMPENSATION_COMPLETED`、`UNRESOLVED`；reason 必填。
- `expected_version` 乐观并发；重复/过期决议 409；每次决议与 audit_log 同一事务（审计失败即回滚）。
- 决议只记录人工结论，不删除远端资源，不触发自动重试；resolve 后 Begin 仍 blocked。
- `scripts/ops_external.sh list|resolve` 为管理员 CLI（token 从文件读取，不打印 token）。
- 测试：成功、重复 409、缺 reason 400、viewer 403、重启持久化、审计行、审计失败回滚；live IN_FLIGHT 拒绝、lease 过期可处置、CONFIRMED 恢复路径。
- 独立审查 P1/P2 修复：Candidate 扫描真实化并归档；live IN_FLIGHT resolve 守卫；CONFIRMED commit-window 恢复；Caddy 308 使用动态发布端口。剩余 P3 见 §10。
