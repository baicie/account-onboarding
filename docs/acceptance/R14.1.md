## 2. P0 — Alert Queue 并发安全

重写 `internal/alerts/queue.go`：

- 每个条目有稳定 **ID** 和 `PENDING → IN_FLIGHT → RETRY_PENDING` 生命周期；批次使用独立 `batch ID`，不依赖 pending slice 下标。
- Notifier 调用不持锁；成功只确认仍存在的 ID；Resolve/Reconcile 期间已删除的告警不会被复活或计入 sent。
- 失败回退 RETRY_PENDING，attempts 上限 10，按 minInterval 限流；Context Cancel 可重试。
- 并发 Drain 返回 `ErrDrainInProgress`，不会重复发送同一批次。
- 队列有界；drop 只选择 pending/retry，不删除 in-flight；drop 计数准确。
- `Resolve` 清 active+pending；`Reconcile` 按最新规则集清除已恢复项、重新入队再次触发的规则；GET `/v1/ops/alerts` 无副作用，新增显式 admin `POST /v1/ops/alerts/reconcile`。
- QueueStatus 暴露 `ephemeral`、pending、in_flight、delivered、resolved、dropped/sent/deduped，明确重启后内存队列丢失。
- 测试：Drain 阻塞时 Resolve/Reconcile/新增/drop/failure、成功+Resolve、成功+Reconcile re-arm、并发 Drain、Context Cancel、重复 Resolve、retry 限流、1000 次受控并发。
