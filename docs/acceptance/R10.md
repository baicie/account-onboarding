## 2. P0 — IN_FLIGHT / 人工 Resolve 安全收口

- 新增 **migration 0005** 生命周期/审计列（worker_id、lease_generation、resolved_by、resolved_from_status、resolution_version）；schema **5**。
- `CompleteExternalOperation` 现必须提供 **LeaseOwner + FencingGeneration + OperationVersion**，并在事务内复核：
  - 当前 Operation Status；
  - Run lease owner / fencing generation / lease_until；
  - Operation Version；
  - 是否已被管理员 RESOLVED。
- 失去合法租约但远端可能已收到请求：**不覆盖终态**，将 IN_FLIGHT 保守转为 `RECONCILIATION_REQUIRED`（`LEASE_LOST_AFTER_REMOTE_CALL_MAYBE_SENT`），返回 `ErrLeaseLost`。
- **租约过期不等于 Worker 停止**：`Resolve` 完全拒绝 IN_FLIGHT（不再用 lease 过期推断）。单进程生命周期屏障：
  - 启动（单写锁已证明旧进程死亡）时：PREPARED（Mark 之前，不可能已调用 provider）→ `FAILED_DEFINITE`；IN_FLIGHT → `RECONCILIATION_REQUIRED`；
  - `Engine.Stop` 排空 workers 后同样处理遗留 IN_FLIGHT；
  - 人工只能处置非 IN_FLIGHT 状态；迟到的 Worker completion 不能覆盖 RESOLVED。
- 失败测试（确定性，不依赖 sleep）：stale lease completion、late worker vs admin resolve、PREPARED/IN_FLIGHT 恢复区分、version mismatch、重复 completion、admin resolve 重复、audit 失败回滚、live IN_FLIGHT 拒绝。

## 3. P1 — 审计身份与溯源

- Resolve actor 来自已认证凭据，而非请求 JSON：`bearer:admin:sha256:<token指纹>` / `bearer:viewer:...` / `cookie:operator`；不记录 token 本身。
- Audit `run_id` = 操作所属 Run；Detail 包含 `operation_id`、from/to status、version before/after、actor、requested_at_ms、resolved_at_ms、resolution、reason、evidence_reference、provider/type。
- 状态修改 + audit 写入同一事务；审计表缺失/写入失败时 resolve 整体回滚（测试）。
- 输入校验：reason 非空、≤2000 字符；evidence ≤512；拒绝 NUL/CR/LF；Viewer 403；重复/过期版本 409；空/非法 reason 400；未知 ID 404。
- Cookie 路径仍走既有 CSRF + Origin + session revocation 校验。

## 5. P3 — Release Dry Run（无生产发布）

`tests/r10/registry_dry_run.sh` + `r10-dry-run.yml`（真实 CI，**15/15 PASS**）：

1. 固定 commit 构建镜像并验证镜像内 commit。
2. SBOM/provenance（supply_chain.sh）。
3. 启动 **临时本地 OCI registry:2.8.3**，push 到 `127.0.0.1:<端口>`。
4. 读取 Registry Manifest Digest，校验 Registry `Docker-Content-Digest` 一致；拉取已服务的 manifest、构造**合法但内容不同**的 manifest 对同一 digest PUT，registry 以 400 拒绝（内容寻址不可变），不再用非法 `{}` body 作为证据。
5. 删除本地镜像，按 digest 拉取到干净镜像名，再次验证二进制/commit。
6. 下载 **cosign v2.4.1** 并校验官方 SHA-256 后才执行；记录版本。
7. 测试密钥签名 → verify；生成 provenance → attestation → verify；**解码 DSSE payload 验证 commit 绑定**。
8. 临时 registry/镜像/密钥全部清理；未 push GHCR、未创建 Release/Tag。

P2-1/P2-2 复审修复：基础镜像 ARG 已含 digest 时不再二次拼接（最终 metadata 为单一 `tag@sha256:…`）；digest immutable 用合法不同 manifest 的 HTTP 400 证明。最终 supply/candidate/dry-run CI 在 `d9bcc6f` 复跑通过。
